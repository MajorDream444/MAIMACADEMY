# MAIM Academy ABCs — Volume 2: Build and do

**Founder supplied:** 1 November 2026 (Asia/Makassar). **Status:** selected working A–Z map for Academy curriculum and project planning. This records the supplied wording, not proof that 26 workshops, assignments or paid products are ready.

Major AI Mindset carries the philosophy of how people see, decide and grow. MAIM Academy teaches them to turn an idea into something that works. These are workshop themes and project prompts, not a required alphabetical course sequence.

| Letter | Academy action | What the learner does |
| --- | --- | --- |
| A | Audit | Find a real problem or repetitive task worth solving. |
| B | Build | Make the first working version. |
| C | Connect | Link the tools, data, and people the solution needs. |
| D | Design | Map the user’s journey and the result they need. |
| E | Evaluate | Check whether the output is useful and accurate. |
| F | Flow | Turn scattered steps into a repeatable workflow. |
| G | Guard | Set permissions, review points, and data boundaries. |
| H | Handoff | Make the work usable by someone besides its creator. |
| I | Integrate | Bring the solution into an existing business process. |
| J | Journey | Trace what happens from first contact to final result. |
| K | Knowledge | Organize source material so AI can use it responsibly. |
| L | Launch | Put a tested version in front of real users. |
| M | Measure | Track time saved, quality, adoption, or revenue. |
| N | Navigate | Handle failures, exceptions, and changing requirements. |
| O | Optimize | Improve the part that slows the system down. |
| P | Prototype | Test an idea quickly before a full build. |
| Q | Quality | Review outputs against clear acceptance standards. |
| R | Refine | Use feedback to improve the next version. |
| S | Ship | Deliver a complete, usable piece of work. |
| T | Test | Check the workflow with realistic cases. |
| U | Use | Practice with the tools in an actual task. |
| V | Validate | Confirm that the solution solves the original problem. |
| W | Workflow | Document who does what, when, and with which tool. |
| X | eXchange | Move information reliably between systems. |
| Y | Yield | Show the outcome the build produced. |
| Z | Zero to One | Take the next idea from blank page to working proof. |

## Teaching use

A useful opening project path is **Audit → Design → Prototype → Test → Ship → Measure**. Learners can return to Guard, Knowledge, Quality and other letters wherever the project requires them. Each Academy module should end with a concrete assignment or artifact and a review criterion. “Learn it, build it, use it” expresses the intent; it is not a claim of measured outcomes.

This map does not replace the existing 30-Day Major Moves proposal, change its schedule or pricing, activate checkout, or imply operational learner records. Align future lesson work deliberately, with source, rights, accessibility and safety review.
